# 《AI 战争模拟器》方案总览（v2 · 待确认）

> 首战《围魏救赵 / 桂陵之战》。本文是对你原始方案的优化版：先说清改了哪里、为什么改，再给技术栈与里程碑。
> 细案见 [游戏设计](01-游戏设计.md)、[技术架构](02-技术架构.md)、[合规与发布](03-合规与发布.md)。

## 一句话定位

历史战场推演 + 关键节点决策 + 有限情报博弈。玩家扮演齐国最高决策层，只能看到**前线战报**和**最新势力范围**，看不到兵力、士气、粮草的具体数字；战场由规则内核与敌方 AI 推演，结果不必与史实一致。

一局约 5–8 分钟（推演约 2 秒/日，决策时自动暂停），7–8 个关键节点，4 档难度，移动端竖屏优先（B 站 App 内打开）。场地视觉为极简地图风。

## 一、对原方案的 8 处关键改动

### 1. 运行时不再调用大模型，改成"离线语料 + 运行时模板拼装"

原案让 LLM 解析军令、撰写战报、生成参谋意见。**Toy 是纯静态页面，不能请求外部服务**（平台禁止站外跳转与外部接口依赖，包体安全检查也会拦 XHR/WebSocket/fetch 一类写法）。这条在平台上做不通。

改法：把 LLM 用在**开发期**——批量生成战报、参谋、使节、降卒、结局文案，人工筛掉重复与出戏的句子，存成语料 JSON 随包发布；运行时按「事件类型 × 来源 × 可信度 × 语气」组合出句子。代码里留一个 `NarrativeProvider` 接口，将来平台若开放 AI 能力，可以整体替换而不动推演内核。

代价是老玩家读到几十条之后可能认出句式；补偿办法是**组合式生成**（三段独立抽取，排列组合上千种）+ 语料分档 + 同模板短期不复用。这个成本比"平台直接不给过"低得多。

### 2. 自由文本军令 → 军令拼装器

Toy 明令禁止 UGC 能力（`<textarea>`、`contenteditable`、文件上传都会被判违规，你给的 check-toy.mjs 第 9 条扫的就是这些）。自由输入这条路是死的。

改成**四步点选**：受令部队 → 任务（行军/驻守/佯攻/强攻/设伏/追击/撤退/休整/征粮/侦察/联络）→ 目标（点地图选城邑/道路/方向）→ 修饰（疾行/隐蔽/示弱/夜行/弃辎重）。选完实时生成一句军令预览：

> 令田忌率中军、轻车，自平陆隐蔽行军至大梁西郊；沿途不接战。

可表达的意思不比原案的自然语言示例少，还没有歧义、不需要解析、点两下就完成。**这是被迫改的，但改完体验更好**——原案的自然语言输入在手机上也不好打字。

### 3. 补上"日常军令"层

原案只有 7 个节点，两个节点之间玩家只能干等推演。加一层轻量操作：每旬（10 天）获得 1 枚**军令牌**，可以派斥候查某条路、征粮、遣使联楚/联秦/安抚宋卫、犒军、审讯降卒、严查假消息。指令有 1–3 天传令延迟，结果以战报形式回来。

作用：让"情报也是资源"落到实处，玩家不用上帝视角也能主动影响局势；同时不破坏"只能看战报和势力范围"的规则。

### 4. 敌方 AI 拆成"庞涓 + 魏廷"两个脑

原案把魏军做得像一个理性整体。史实里真正的张力是：**庞涓想打下邯郸立功，魏王怕大梁有失**。所以：

- **庞涓**按「战功 / 大梁威胁 / 邯郸破城进度 / 部队疲劳 / 自身声望」算效用，性格激进、重名。
- **魏廷**维护一个"大梁政治压力"值，涨到阈值就**强令回师**；庞涓可能抗命拖延，也可能连夜急行。
- 两者冲突时，才出现"回不回、什么时候回、走哪条路"的变数——**围魏救赵之所以成立，靠的就是这个结构性矛盾**。

玩家看到的不是"敌军 AI 等级"，而是战报里"大梁城门戒严、魏王征发民夫"这类政治信号。

### 5. 秦、楚从"背景板"变成"战略杠杆"

《战国策·齐策一》记段干朋主张南攻襄陵以弊魏；《战国策·楚策一》记楚使景舍救赵、取睢濊之间；《史记·秦本纪》记秦在魏东征时攻魏河西。三条史料给了现成的多线战场。

方案做成**外交时钟**：玩家遣使联楚/联秦，成功则若干日后南线、西线开打，魏国被迫分兵或延迟回援；宋、卫作为缓冲国，态度影响粮道安全与平陵方向能不能打。玩家用"使节"资源换战略空间，而不是靠数值暴兵。

### 6. 数字全部藏起来，结算才揭晓

不显示兵力、伤亡、士气、粮草数值，只用定性词：兵势「众/寡/相当」、折损「小挫/损兵/大溃」、粮草「足/将尽/已断」、士气「振/疲/惰」。

结算页解锁真实战果（双方损失、城邑易手、时间线），作为复盘奖励。这是"信息即玩法"的核心：玩家必须从措辞、来源、延迟里判断局势。

### 7. 确定性内核 + 决策日志存档

同一随机种子 + 同一串决策 = 同一结局。存档只存种子、决策记录和节点状态，体积压在 50KB 以内；平衡调参时可以无头批量跑局，以后做排行榜也能用种子复算成绩。

### 8. 数据驱动，给后续战役留好接口

战役 = 一份内容包（地图节点、部队、决策节点、触发条件、语料、史实注）+ 通用内核。新增《长平之战》只需加内容包；《赤壁之战》涉及水战，需要扩展一个水战模块，这一层边界在技术文档里写清楚了。

## 二、一局游戏怎么走

1. **标题页**：选战役、选难度、继续上局；史实说明入口。
2. **战前简报**：150 字背景 + 目标 + 初始态势图（无精确兵力）+ 信息边界提示。
3. **战场页**：左侧/上方势力范围图，右侧/下方战报流。推演按日推进，可暂停、加速、跳到下个节点。
4. **关键节点**：推演暂停，弹出决策面板（2–4 个方案 + 军令拼装）。决策窗口内不选，则按难度用默认方案，质量随难度下降。
5. **日常军令**：节点之间每旬 1 枚军令牌，派斥候、征粮、遣使、犒军。
6. **结算**：S/A/B/C/D 评级、各项得分、关键决策时间轴、真实战果、史实对照与偏离度、重开/换难度。

## 三、技术栈（推荐）

| 层 | 选择 | 理由 |
|---|---|---|
| 工程 | pnpm workspace + Vite + TypeScript（strict） | 和你现有四个项目同一套约定，自检脚本可直接复用 |
| UI | Vue 3（`<script setup>`） | 熟悉、体积小、SFC 写面板效率高 |
| 地图 | **手绘 SVG**（Vue 组件渲染） | 20 个节点量级，SVG 足够；可样式化、可点击、可做迷雾与控制区，比 Canvas/WebGL 省事且包体小 |
| 推演内核 | 纯 TS 包，零 DOM 依赖 | 可单测、可无头跑万局做平衡 |
| 叙事 | 语料 JSON + 模板拼装 | 运行时零网络 |
| 存档 | localStorage + 平台云存档适配层（可选） | 云存档/排行榜按 Toy 限流规则做，失败静默降级 |
| 运行时第三方库 | **只有 Vue** | 自检脚本的第三方安全基线可以保持为空，少一层审核风险 |

**不用 Phaser**：这游戏只有地图和面板，不需要游戏引擎；Phaser 的 Loader 带 XHR，还会让包体凭空大几 MB，你现有项目的 `knownVendorHits` 就是为这类问题打补丁。**不用 CDN、外部字体、AI 接口**：Toy 跑在 `/toy/<slug>/` 子路径下，外部依赖权限还在收紧，全本地最稳。

## 四、首发范围

**做**：单战役《围魏救赵》、4 档难度、7 个关键节点 + 日常军令、完整推演/情报/评分/存档、移动端优先 UI、史实说明页、封面与图标。

**不做**：排行榜与云存档强依赖（留适配层）、战史回放、多语言、配音、其他战役。

## 五、里程碑与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| M1 | 脚手架、`base:'./'`、自检脚本接入、三端布局骨架、静态地图 | `pnpm build` 后 `toy:check` 0 error |
| M2 | 推演内核：时间、行军、粮草、遭遇战、士气疲劳 | 单测通过；同种子两跑状态哈希一致 |
| M3 | 情报系统、战报语料、势力范围与迷雾 | 假报/延迟/误差按难度生效，定性描述不泄露数值 |
| M4 | 7 个决策节点、军令拼装器、庞涓/魏廷 AI | 每节点可触发；AI 会因大梁压力回师，也会抗命 |
| M5 | 评分、结局、存档、结算页、平衡调参 | 无头批量跑：史实打法 S/A 占比 40–60%，硬碰打法明显掉档 |
| M6 | 美术打磨、移动端、音效、合规自检、打包发布 | `pnpm check` 全绿，真机试玩无白屏 |

## 六、需要你确认的事

1. **技术栈**：Vite + Vue 3 + TS + SVG，运行时只依赖 Vue（推荐）。
2. **军令输入**：已确认点选式军令牌拼装器（自由文本受平台 UGC 禁令限制，不可用）。
3. **叙事方式**：已确认开发期语料 + 运行时模板拼装（运行时不能调大模型）。
4. **美术风格**：已确认「极简地图风」——纸白底、细线、低饱和势力色、无纹理无滤镜。
5. **单局时长**：约 5–8 分钟（推演约 2 秒/日 + 决策停留时间）。

方案已确认，按 M1→M6 开发。
