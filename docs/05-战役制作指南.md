# 05 · 新增战役制作指南

> 目标读者：要加一场新战役的开发者。现有五场战役（围魏救赵走 legacy 引擎，其余四场走 ops 引擎）作为模板。
> 一场新战役需要 4 处改动：数据、规则、语料、注册。预计 2–4 小时可完成一场。

## 0. 先判断用哪个引擎

| 引擎 | 适用 | 现状 |
|---|---|---|
| legacy（packages/sim/src/game*.ts） | 围魏救赵，单地图、固定魏军回师逻辑 | 不再扩展，仅维护 |
| ops（packages/sim/src/opsEngine.ts） | 所有新战役：多势力、多决策节点、自定义胜负 | 推荐 |

新战役一律用 ops。下文只讲 ops。

## 1. 目录结构

~~~
packages/content/src/ops/<campaign>/
  data.ts     # 地图、部队、决策节点、难度、胜负平衡
  rules.ts    # 敌方 AI、节点触发、选项效果、胜负判定、评分、HUD
~~~

参考顺序（由简单到复杂）：

1. feishui/ —— 6 支敌军、分批到达、后撤崩溃（最简单的自定义机制）
2. chibi/ —— 联盟、水战、火攻与风向（概率判定）
3. huaihai/ —— 五兵团、政治时钟南撤、合围与围歼（最复杂的阶段推进）
4. siduchishui/ —— 多势力接缝、佯动、渡口（机动性最强的）

## 2. data.ts：五块内容

### 2.1 meta

~~~ts
meta: {
  id: 'xxx-yyyy',            // 唯一 id，存档键与规则注册都用它
  title: '战役名',
  subtitle: '年代 · 双方',
  era: '朝代/战争',
  premise: '一句话态势（标题卡用）',
  dateLabel: '纪年 · 起始状态',
  startLabel: '第一日',
  playerRole: '玩家扮演的职务（不具名）',
  background: '战前背景，150–250 字',
  objective: '胜利目标，一句话',
  infoTip: '给玩家的情报提示',
  dossier: [{ title: '标题', text: '...' }],  // 战前史料页，6–8 条
  disclaimer: '写意改编免责声明',
}
~~~

### 2.2 地图

~~~ts
mapWidth: 700, mapHeight: 700,   // 设计坐标，UI 会自适应缩放
cities: OpsCityDef[]   // 12–20 个节点
roads:  OpsRoadDef[]   // 20–35 条边，days = 行军天数
~~~

- 城市属性：owner（势力 id）、kind（city/fort/port/capital）、terrain（plain/mountain/river/city）、garrison（守军）、wall（城防系数）、grain（存粮）。
- 道路属性：kind 为 river 时需要渡河（引擎会累计 vars.riverCrossings）；rail / road 仅供 UI 与叙事区分。
- 坐标只需大致方位正确，不必与真实经纬度吻合；节点间距应体现档案里的行军日数。

### 2.3 势力

~~~ts
playerFaction: 'red',
enemyFactions: ['kmt', 'sichuan'],
factions: { red: { name:'红军', color:'#8a3b3b', short:'红' }, ... }
~~~

### 2.4 部队

~~~ts
armies: OpsArmyDef[]  // 玩家 3–6 支，敌方 4–8 支
~~~

关键字段：troops、morale、fatigue、training、foodDays、city（初始位置）、stealth（隐蔽度，影响被侦测）、naval（是否水军，水路过河需要）。

### 2.5 决策节点

~~~ts
decisions: DecisionNodeDef[]   // 6–8 个
{
  id: 'd1', title: '标题', prompt: '态势描述（给玩家看的）',
  options: [
    { id: 'opt1', label: '方案', desc: '具体行动', hint: '风险提示', recommended: true },
    // 3–4 个选项
  ],
  defaultOption: 'opt1',   // 超时默认
}
~~~

- 选项必须是"可执行的动作"，不是"态度"。写成"全军向 X 城开进"而不是"积极应对"。
- 至少一个选项带 recommended: true（史实选择），UI 会显示"荐"标记。
- 每个选项都要有代价，不能有纯优解。

### 2.6 难度与平衡

~~~ts
difficulty: { hist, normal, hard, hell }   // 四档，字段见 packages/sim/src/types.ts 的 Difficulty
balance: {
  battleIntensity,        // 战斗强度（大兵团战役调低，避免一仗打崩）
  attackerLossCap,        // 单日攻方损失上限（大兵团攻坚必设）
  defenderLossCap,
  routTroopRatio, routMorale,                 // 溃退阈值
  supplyFactor, maxFoodDays, resupplyDays,    // 补给
  siegeGarrisonLoss, siegeGrainLoss,          // 围城
  desertionPerDay,                            // 断粮减员
}
~~~

难度原则：难度不放大分数（scoreFactor 一律 1），差异体现在情报质量（intelDelay / strengthError / falseReportPerTenDays）、决策窗口（decisionSeconds）、补给（supplyFactor），以及规则里按 state.difficulty 写的行为阈值（例：赤壁火攻成功率、淝水秦军自乱概率、淮海支前运力消耗）。

## 3. rules.ts：九个钩子

~~~ts
const rules: OpsRules = {
  id: 'xxx-yyyy',              // 必须与 data.meta.id 一致
  opening(state, campaign, narrative) {},      // 开局战报 + 初始命令
  triggerNode(state, campaign) { return 'd1' },// 返回下一个该弹的节点或 null
  applyDecision(state, campaign, narrative, nodeId, optionId) {},  // 选项效果
  aiTick(state, campaign, narrative) {},       // 敌方 AI，每天调用
  onTick(state, campaign, narrative) {},       // 每日结算（事件、围歼、投降等）
  checkEnd(state, campaign) {},                // 设置 state.over / state.endingId
  score(state, campaign): OpsScore {},         // 评分 + 结局文案
  hud(state, campaign) {},                     // 顶栏文案
  powerMod(state, campaign, armyId, side) {},  // 可选：战力修正
}
~~~

### 3.1 triggerNode 的写法（最容易出错）

- 必须严格顺序：if (!has('d2') && has('d1') && ...) return 'd2'。漏了 has('d1') 会导致节点乱序弹出。
- 条件 = 位置条件 或 天数兜底：(at('x') || day >= N)。天数兜底要留足玩家机动时间。
- 一次只返回一个节点；引擎会暂停推演等待玩家决策。

### 3.2 敌方 AI 的写法

不要每回合都让敌军精准追玩家（会变成"读心"）。推荐两种模式：

1. 情报滞后：每 N 天刷新一次目标，且目标取"最近一次侦察到的位置"（见四渡赤水）。
2. 阶段推进：按天数/事件分批移动（见淮海：第 7 兵团覆灭后徐州集团才南撤；赤壁秦军分批到一线）。

敌军贴到玩家 1 天路程就停下，体现"不敢硬碰"，也避免反复开战锁死。

### 3.3 胜负与评分

- checkEnd 里设置 state.over = true; state.endingId = 'xxx'，结局 id 会被 score() 映射成文案。
- score() 返回 { grade, total, parts, endingId, endingTitle, endingText, deviation, highlights, lines }。
- 评分建议：目标达成 30 + 保存实力 20 + 歼敌 15–20 + 特色机制 15 + 节奏 5，总分 100。S≥75、A≥66、B≥54、C≥40。
- powerMod 只做"态势修正"（如被围部队防御下降），不要用来给敌军加难度数值。

## 4. 注册（三处）

1. packages/content/src/ops/narrator.ts：如有新语料键，在 BASE 里加（可选）。
2. packages/content/src/packs.ts：

~~~ts
import { xxxCampaign } from './ops/xxx/data.js'
import xxxRules from './ops/xxx/rules.js'

export const xxxPack: OpsPack = {
  id: xxxCampaign.meta.id,
  engine: 'ops',
  meta: { ...从 xxxCampaign.meta 映射... },
  difficulty: xxxCampaign.difficulty,
  tasks: [/* 行军、佯动、强攻、设伏、追击… */],
  unitsLabel: '我军', enemyLabel: '敌军',
  campaign: xxxCampaign, narrative: makeOpsNarrator(), rules: xxxRules,
}
export const PACKS: Pack[] = [guilingPack, ..., xxxPack]
~~~

3. packages/content/test/regression.test.ts：在 HISTORIC_PICKS 里加历史路线选项，并加一条断言：

~~~ts
it('xxx 历史路线可达 X 以上', () => {
  const best = assertProgress('xxx', xxxCampaign, xxxRules, 'B')
  if (!['结局1', '结局2'].includes(best.endingId)) throw new Error('...')
})
~~~

## 6. 常见坑

| 现象 | 原因 | 修法 |
|---|---|---|
| 节点乱序弹出 | triggerNode 缺少前置 has('dN') | 加严格顺序链 |
| 部队原地不动 | 战斗后 order 丢失 | 引擎已用 orderMemory 恢复，规则里别覆盖 |
| 大兵团一仗打崩 | 攻/守方按百分比掉血 | 设 attackerLossCap / defenderLossCap |
| 歼敌数恒为 0 | 只击退不歼灭 | 在 onTick 里按建制比例判"被围歼" |
| 难度无感 | 只在分数字段上做差异 | 用行为阈值（成功率/概率/消耗）区分 |
| 弃城后卡死 | 空城无人接管 | 引擎已自动接管，规则里别阻止 |
| 分数倒挂（越难分越高） | scoreFactor 放大 | scoreFactor 一律 1，难度走行为 |
