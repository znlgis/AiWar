## 1. 工作方式

- 方案确认后按里程碑开发，每个里程碑结束时给可运行的构建产物和验收说明，不一次性堆完再给你看。
- 先把 `check-toy.mjs` 接进来当闸门，之后每次构建都跑，避免最后才发现包体安全问题。
- 内容（战报语料、节点文案）与代码分离，方便你自己改词、加结局，不用动内核。

## 2. 里程碑明细

### M1 脚手架与合规闸门（约 1 个工作段）

交付：
- pnpm workspace；`apps/site`（Vite + Vue 3 + TS）、`packages/sim`、`packages/content`。
- `vite.config.ts` 设 `base: './'`、`target: 'es2018'`、vendor 拆分、关 sourcemap。
- `scripts/check-toy.mjs`（你的脚本 + 本作 CONFIG）。
- `scripts/preview-toy-subpath.mjs`：把 dist 挂到 `/toy/aiwar-guiling/` 下做子路径预览。
- 三端布局骨架：顶栏、地图容器、战报流、底部控制条；标题/简报/战场/结算四个视图的空壳。
- 静态地图：从 `map.json` 渲染地形、河流、道路、城邑。

验收：`pnpm dev` 能打开；`pnpm build` 后 `pnpm toy:check` 0 error；子路径预览资源全部 200。

### M2 推演内核（最大的一块）

交付：
- `types / rng / engine`：按日推进、按域拆随机流、确定性可复现。
- `movement`：道路日数、疲劳、隐蔽、行军修饰、到达与遭遇判定。
- `combat`：地形兵种克制、战力公式、逐日损失、崩溃与溃退、伏击修正。
- `siege`：城墙、粮草、城防、援军触发。
- `logistics`：粮草、补给线、征粮、逃兵。
- `morale`：士气与疲劳。
- 单测 ≥ 25 条，覆盖公式边界、确定性、无负数。
- 调试用 `pnpm --filter sim demo`：控制台打印 60 日推演日志。

验收：同种子两跑逐 tick 哈希一致；会战 3–8 日收敛；补给线断掉后粮草递减、逃兵出现。

### M3 情报与战报

交付：
- `intel`：侦察覆盖、探测概率、兵力带、置信度、踪迹衰减、假情报。
- `reports`：事件 → 战报模板参数 → 文案（三段式组合、同模板冷却）。
- 语料：≥12 类、≥120 条模板（开发期用 AI 批量生成后人工筛；你后续也能直接改 JSON）。
- UI：战报流、来源/可信度/送达时间、筛选、重要战报标记；势力图迷雾、控制区、已知敌踪、补给线。

验收：难度越高延迟越长、误差越大、假报越多；界面任何位置不出现敌方真实数字。

### M4 决策与敌 AI

交付：
- 7 个决策节点：触发条件、选项、默认选项（超时）、定性后果提示、决策窗口倒计时。
- 军令拼装器：部队/任务/目标/修饰四步 → 军令预览 + 参谋风险提示 → 执行（含传令延迟）。
- 日常军令：军令牌池、7 种指令、效果延迟与战报反馈。
- `ai/pangjuan`：效用决策、性格、急行军、路线选择、识破判定、抗命。
- `ai/weiCourt`：大梁政治压力、强令回师。
- `ai/zhao|songwei|chuzin`：守城、站队、外交时钟。

验收：每节点都能触发；玩家不救赵也能走到结局；大梁被威胁时魏军会回师，困难难度会换路线或反制；军令拼装器能表达原方案的自然语言示例（"偏师攻平陵、只许败不许胜；主力昼伏夜行趋大梁；斥候查回师路线"）。

### M5 评分、结局、存档、平衡

交付：
- 评分（8 维加权 + 难度系数）、9 种结局、结算页（评级、得分、真实战果、关键决策时间轴、史实对照、偏离度）。
- 存档：自动存档、读档、损坏兜底；确定性回放。
- 无头平衡脚本 + 参数表；按验收指标调参。
- 首局引导：3 分钟带教（第一份战报 → 第一个决策 → 信息边界说明）。

验收：平衡指标达标（普通难度史实路线 A/S 40–60%、D < 10%、四档难度分数单调）；读档继续与不中断结果一致。

### M6 打磨与发布

交付：
- 美术打磨（宣纸/墨色体系、印章评级、简牍战报卡、动效节流）。
- 移动端：竖屏优先、横屏适配、手势缩放、安全区适配。
- 音效（WebAudio，可关）。
- 全面合规自检：check-toy、toy_doctor、断网游玩、无 UGC 扫描、敏感词扫描。
- 封面（1200×900）与图标；发布包；`toy create/update` 预览。

验收：见 `03-合规与发布.md` 的发布前检查清单。

## 3. 内容扩展：新增战役

新增一场战役 = 新建一个内容包目录：

```
packages/content/src/campaigns/<campaign-id>/
├─ campaign.json     # 元数据、日期、难度参数、评分权重、胜利条件
├─ map.json          # 节点、连线、区域 path、河流、地形
├─ units.json        # 初始部队、将领
├─ decisions.json    # 决策节点、触发条件、选项、默认选项
└─ corpus/*.json     # 该战役语料（可复用通用语料 + 战役专属）
```

内核通用逻辑不动，新增内容包后在 `campaigns/index.ts` 注册即可。

- **陆战类**（长平、官渡）：直接复用；长平需要"包围/断粮"参数，官渡需要"营垒/火攻"参数，可在内核加可选机制开关。
- **水战类**（赤壁）：需要水军兵种、水域通行、火攻蔓延、风向系统，建议作为内核 v2 单独立项，不塞进首版。
- 每场战役独立 `campaignId`，存档、评分、排行榜按战役隔离。

## 4. 后续可能加的玩法

- 战史回放：把决策日志按日播放，适合视频二创。
- 每日挑战：固定种子 + 全网同局，配合排行榜。
- 更多"军师意见"人格：不同军师给不同倾向的建议（孙膑偏奇、田忌偏稳）。
- 战役编辑器（开发者工具，不打包发布）。

## 5. 需要你提供或确认的信息

- 发布权限与 Toy CLI 登录（首发时需要）。
- 封面素材偏好（用游戏内画面生成，还是另外画一张）。
- 是否要排行榜/云存档（需要先在发布平台创建榜单与共享存档标识，涉及账号配置）。
- 对水墨风格的接受度（可先出 M1 静态地图给你看一眼再定稿）。
