## 1. 需求二：战报与战役分析（完成）

### 1.1 内核加了四个只增不删的账本

`packages/sim/src/ledger.ts`（新）：

```ts
battleLog: BattleRecord[]   // 每场仗：地点/日序/天数/双方折损/胜负/是否伏击/我方在哪边
cityLog:   CityRecord[]     // 每次易手：城/日序/原属/新属/缘由
choiceLog: ChoiceRecord[]   // 每次定策：节点/选项/日序/是否史实项/是否逾时执行
orderLog:  OrderRecord[]    // 每次军令：日序/任务/受令部队/结果（ok|void）/作废原因
```

写入点在 `opsEngine.ts`（battleTick / resolveBattle / siegeTick / moveArmies /
issueOpsOrder / resolveOpsNode / timeoutOpsNode）与 `battle.ts`、`nodes.ts`、`orders.ts`、`engine.ts`。

**账本只 push，不参与判定。** 两处证据：`regression.test.ts` 的评级与分数逐位未变；
`debrief.test.ts` 有一条「同 seed 同决策 → 同 tick / 同总分 / 同 endingId」的用例。

旧存档兼容：`normalizeLedgers()` 把缺失字段补成空数组，`save.ts` 合并后调用。

另外补了 `Battle.firstTick`（开战日序）与 `attackerLost/defenderLost`（按日累计），
否则战报里说不出「这场仗打了几天、折损多少」。

### 1.2 战报生成器

`packages/sim/src/debrief.ts` + `debriefAdapters.ts`（新）——纯函数、零 DOM：

| 字段 | 内容 |
|---|---|
| `verdict` | win / lose / draw / abandoned，由 `verdictOf(campaignId, endingId)` 归档 |
| `headline` | 一句话战果：接战几阵（胜/负/平）、城邑易手几次、胜败反差时点破「胜负手不在阵前」 |
| `chronicle` | 编年：定策 / 交战 / 易手 / 军令作废 / 日志补缺，按日序排序，可切「要点 / 全部」 |
| `battles` | 每仗胜负与我方视角折损分档（小挫/折损/损兵/大损/溃散） |
| `metrics` | 历时、交战、双方折损、城邑变动、决策偏离数、军令生效/作废 |
| `reading` | 把 `score.parts` 每项翻成人话（`reading.length === parts.length` 有测试锁） |
| `turningPoint` | 首场伏击胜 > 我们丢城 > 首场败战 > 首场胜战 > 首日定策 |
| `historyCompare` | 贴近史实 / 与史实不同，两列 |
| `hintIfLose` | 失败时的「如果当时……」，按战役各写一句 |

`debriefToText()` 输出纯文本，供结算页「复制文本」（不落文件、不触平台 UGC 规则）。

### 1.3 「不论输赢」的三条路径

| 路径 | 改前 | 改后 |
|---|---|---|
| 胜局 | 结算页只有分数 | 战报 + 分析 |
| 败局 | 结算页只有分数 | 战报 + 分析 + 「如果当时」 |
| **主动放弃** | **直接删档回标题，什么都不留** | 先出残局战报（verdict=abandoned），再由玩家决定是否丢弃 |

`store/game.ts` 的 `abandon()` 改为 `finish(true)`；结算页底部多一个「丢弃本局」。

### 1.4 顺手修掉的两个既有 bug

1. **围魏救赵的结算页一直是全白的**。legacy 引擎从不把结算写回 `state.score`，
   `projectLegacy` 一直返回 `score: null`，而 `ResultView` 是 `v-if="score"`。
   现在由 `projectNow` 显式传入 `finalize()` 的结果。（本轮自动化截图时发现：
   一路单步到 53 日，DOM 里只有空壳。）
2. **战役专属语料永远轮不到**。`makeOpsNarrator` 把通用语料排在专属语料之前，
   抽取是 `salt % length`，通用池没抽完就轮不到专属语句。现已改成专属在前。

## 2. 需求一：五场战役加细节（完成）

四场 ops 战役各自补齐数据、规则与专属语料（围魏救赵走 legacy 引擎，只加了地形与战后语料）：

| 战役 | 城邑 | 道路 | 部队 | 决策节点 | 专属语料 | 空选项 |
|---|---|---|---|---|---|---|
| 赤壁 | 12→24 | 15→49 | 8→15 | 7→10 | 0→179 条（39 key） | 15→0 |
| 淝水 | 18→26 | 20→48 | 10→15 | 8→11 | 0→179 条（43 key） | 24→0 |
| 四渡赤水 | 20→26 | 29→52 | 13→14 | 8→11 | 0→185 条（44 key） | 8→0 |
| 淮海 | 17→26 | 21→50 | 12→16 | 8→12 | 0→162 条（40 key） | 14→0 |

落地的特色机制（都来自 `docs/research/` 的档案，不是现编的）：

- **赤壁**：军中疾疫（每 9 日加深，曹军逐日减员）、连环船（火攻追加损失）、风向窗口（固定窗口日，地狱难度首窗判错）
- **淝水**：洛涧先胜的士气转折、朱序内应的一次性情报、秦军后援分批到达、庙堂猜忌反噬、秦军自乱级联
- **四渡赤水**：佯动欺骗（成功则敌军 2–3 天错向）、渡口船数上限（皎平渡 7 船/日）、扎西整编（补充率减半换机动）、追兵距离、雨季河水
- **淮海**：三线配平（吃/挟/看）、支前运力（雨雪 -30%、连续动员后效率减半）、策反点数（≥4 触发战场转向）、政治时钟 vs 军事时钟

新增两条测试锁住这些不再退化：
- `packages/content/test/decisions.test.ts`：**每个决策选项都必须留下可观测后果**
  （旗标/变量/城邑/部队/军令任一变化）。这把刀先切出了 61 个空选项，现在是 0。
- `packages/content/test/corpus.test.ts`：四场战役同一事件必须说出不同的话；
  且必须覆盖引擎发出的全部通用 key。

## 5. 已知取舍与遗留

1. **淮海的地狱难度做了行为层调整**（对方兵团按难度上浮、我方战力系数下调、
   政治时钟缩短）。原因是原参数下地狱档总分顶到 100，出现「地狱比史实更好拿高分」。
   实测梯度 hist 88 / normal 88 / hard 86 / hell 74，史实不减、地狱不反超。
2. **赤壁 d7（荆州归属）在史实路线里触发不到**：火攻 18–22 日成、26 日即收束，
   `day >= 30` 的条件落空。要让它出现需把触发日提前，这是节奏问题，单独议。
3. **淮海/赤壁/淝水的档案里列了 10 种结局分支，本轮只保留原有 5 个**，
   新机制折叠进评分分项而不是新增 ending。要独立结局需同时改 checkEnd、endings、评分三处。
4. `allcampaigns.test.ts` 里四渡赤水是 `wiped D`，这是改动前就有的基线行为
   （该用例只断言 tick>3 与 decisions>2），不是本轮引入的。
