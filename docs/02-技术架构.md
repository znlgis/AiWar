# 技术架构

## 1. 技术栈

| 项 | 选择 | 说明 |
|---|---|---|
| Node | 24.x（本机 v24.9.0） | 构建与脚本 |
| 包管理 | pnpm workspace | 与现有项目一致 |
| 构建 | Vite（`base: './'`） | 相对路径是 Toy 子路径部署的硬要求 |
| 框架 | Vue 3（`<script setup>` + TS） | 面板/战报/决策交互多，SFC 效率高 |
| 语言 | TypeScript strict | 推演内核类型多，strict 能省大量调试 |
| 地图 | SVG（Vue 组件 + CSS） | 20 节点量级；无需 Canvas/WebGL |
| 测试 | Vitest（内核单测 + 无头对局） | 平衡调参的关键工具 |
| 运行时依赖 | 仅 vue | 第三方库越少，包体安全基线越干净 |
| 音效 | WebAudio 合成 | 无音频文件，零体积 |

不引入：vue-router（单页状态机足够）、Pinia（一个 store 够用）、UI 组件库、地图库、图表库、zod（存档校验手写，避免第三方安全基线）。版本以安装时最新稳定版为准并锁 `pnpm-lock.yaml`。

## 3. 核心数据模型

```ts
type FactionId = 'qi' | 'wei' | 'zhao' | 'song' | 'wei_state' | 'chu' | 'qin'

interface Army {
  id: string
  name: string
  faction: FactionId
  commander?: string
  troops: { chariot: number; infantry: number; cavalry: number; crossbow: number }
  morale: number        // 0–100
  fatigue: number       // 0–100
  training: number      // 0.8–1.2
  foodDays: number
  at: { kind: 'city'; id: string } | { kind: 'road'; id: string; progress: number }
  order: Order | null
  stealth: number       // 0–1，越高越难被侦测
  supply: 'ok' | 'threatened' | 'cut'
}

interface Order {
  id: string
  armyIds: string[]
  task: 'march' | 'hold' | 'feint' | 'assault' | 'ambush' | 'pursue' | 'retreat' | 'rest' | 'forage' | 'scout' | 'diplomacy'
  target?: { city?: string; road?: string; direction?: string; enemyTrace?: string }
  modifiers: ('forced' | 'stealth' | 'feignWeak' | 'night' | 'dropBaggage')[]
  issuedTick: number
  arriveTick: number
}

interface Report {
  id: string
  tick: number            // 发出
  arriveTick: number      // 送达
  source: 'scout' | 'border' | 'deserter' | 'merchant' | 'envoy' | 'court' | 'counsel'
  place: string
  confidence: 'high' | 'mid' | 'low'
  templateId: string
  params: Record<string, string>
  important?: boolean
}

interface KnownState {          // 玩家认知，与 TruthState 分离
  cities: Record<string, { owner: FactionId; known: boolean; contested: boolean }>
  traces: Record<string, { armyId: string; lastSeenTick: number; place: string; strengthBand: string; confidence: number }[]>
  supply: Record<string, 'ok' | 'threatened' | 'cut'>
}
```

`TruthState` 含全部真实数据（敌我兵力、士气、粮草、AI 内部状态），**只在结算页解锁**，不进入 UI 常规渲染路径。UI 只读 `KnownState` 与 `Report[]`，从类型层面杜绝"上帝视角泄漏"。

## 4. 推演内核

### 4.1 时间与顺序

```ts
function advanceTick(state: SimState): TickResult {
  const events: SimEvent[] = []
  updatePolitics(state, rngFor(state, 'politics'), events)   // 魏廷压力、楚秦时钟、宋卫态度、天气
  arriveOrders(state, events)                                // 传令延迟
  moveUnits(state, rngFor(state, 'move'), events)            // 双方同时移动
  updateDetection(state, rngFor(state, 'intel'), events)     // 侦察与误差
  resolveContacts(state, rngFor(state, 'combat'), events)    // 遭遇/会战/伏击/攻城
  updateLogistics(state, events)                             // 粮草、补给线、逃兵
  updateMorale(state, events)                                // 士气与疲劳
  const node = checkNodes(state)                             // 决策节点触发
  const reports = materializeReports(state, events)          // 事件 → 战报（含延迟）
  state.tick += 1
  return { events, reports, pendingNode: node }
}
```

- 每日一次，120 日上限；单 tick 计算量 O(部队² + 节点) 级，实测应远低于 1ms，无需 Worker。
- `advanceTick` 内部可变更 draft；对外暴露的 `SimState` 在存档点序列化。

### 4.2 随机数与确定性

- `mulberry32` 基础 PRNG，按域拆流：`move / intel / combat / ai / events / politics`。每个域独立 seed，避免"多调用一次侦察随机数就改变战斗结果"。
- 全代码禁用 `Math.random`（加一条 Vitest 静态检查或 ESLint 规则），只允许 `state.rng[domain].next()`。
- 确定性测试：同种子 + 同决策序列跑两遍，逐 tick 状态哈希一致；不同机器、不同浏览器结果一致（不依赖时间、浮点平台差异的地方用定点或四舍五入到 1e-4）。

### 4.3 战斗

```ts
function effectivePower(a: Army, terrain: Terrain, ctx: BattleCtx): number {
  const troop = a.troops
  const terrainMod = TERRAIN_MOD[terrain]           // 车步骑弩 × 地形
  const base = troop.chariot * terrainMod.chariot + troop.infantry * terrainMod.infantry
             + troop.cavalry * terrainMod.cavalry + troop.crossbow * terrainMod.crossbow
  return Math.pow(base, 0.9)                        // 规模收益递减
    * moraleMod(a.morale) * fatigueMod(a.fatigue)
    * supplyMod(a.supply) * a.training * commanderMod(a.commander)
    * ctx.weatherMod * ctx.surpriseMod * ctx.intelMod
}

function dailyLosses(atk: number, def: number, kind: BattleKind, day: number): { atk: number; def: number } {
  const intensity = kind === 'ambush' && day === 0 ? 0.12 : kind === 'battle' ? 0.06 : 0.03
  const share = (p: number) => (atk + def) === 0 ? 0 : p / (atk + def)
  return {
    atk: intensity * share(def) * 2 * jitter(0.85, 1.15),
    def: intensity * share(atk) * 2 * jitter(0.85, 1.15),
  }
}
```

- 会战持续到一方崩溃（士气 < 25 或兵力 < 55% 初始），崩溃方进入溃退，追击损失按骑兵占比与地形放大。
- 伏击：设伏方首日 `surpriseMod = 1.9`，被伏方首日士气 −25；若情报泄露（识破判定成功），反转：`surpriseMod = 0.75`，设伏方士气 −15。
- 攻城：守方 `wallMod = 2.2–3.0`，攻方粮草消耗 ×2；守方粮尽后每日城防 −(攻方战力比)，城防归零城破；援军抵达触发"撤围/打援"AI 决策。
- 所有系数集中在 `packages/content/.../campaign.json` 的 `balance` 段，便于无头调参。

### 4.4 情报

```ts
function detectChance(target: Army, scouts: ScoutCoverage, ctx: DetectCtx): number {
  const base = 0.25
  return clamp01(base * scouts.coverage * (1 / (0.5 + target.stealth))
    * ctx.terrainMod * ctx.weatherMod * ctx.distancePenalty * difficulty.scoutEfficiency)
}

function sighting(target: Army, difficulty: Difficulty, rng: Rng): Sighting {
  const error = gaussian(rng) * difficulty.strengthError     // ±20%~65%
  const estimate = target.total * (1 + error)
  return {
    strengthBand: band(estimate),                              // 数万/万余/数千/不详
    confidence: pickConfidence(estimate, rng),
    lastSeenTick: state.tick, place: placeOf(target),
  }
}
```

- 已知追踪（trace）随时间衰减：超过 N 日先变"最后见于"，再淡出。
- 假情报按难度生成"敌方故意释放"的目击，与真报混在同一流里，来源、可信度格式完全一致，不做任何 UI 标记。
- 战报模板与数值分离：数值只参与选词（"数万" vs "万余"），绝不渲染具体数字。

### 4.5 敌方 AI

效用函数每日打分，加少量随机扰动（同难度不同种子走法不同）：

```ts
function pangjuanDecision(wei: WeiAIState, known: EnemyKnown): Action {
  const threatCapital = threatToCapital(known)          // 齐军距大梁、兵力估计、动向
  const siegeProgress = siegeProgressOf(wei)            // 邯郸城防/粮草
  const kingPressure = wei.kingPressure / 100
  const fatiguePenalty = wei.fatigue / 100

  const options = [
    { a: 'continueSiege',  u: 2.0 * siegeProgress + 0.4 - 1.6 * threatCapital - 1.0 * kingPressure },
    { a: 'fullReturn',     u: 1.9 * threatCapital + 1.3 * kingPressure - 0.6 * fatiguePenalty },
    { a: 'splitReturn',    u: 1.2 * threatCapital + 0.8 * siegeProgress - 0.2 * fatiguePenalty },
    { a: 'counterAmbush',  u: wei.suspectsFeint ? 1.6 : -1 },
  ]
  return argmaxWithJitter(options, wei.rng, wei.aggression)
}
```

- 性格参数：`aggression`（激进）、`reputation`（重名）让"邯郸将破时抗命"成为自然结果。
- 魏廷独立结算压力值：齐军入魏境 +、逼近大梁 ++、焚积聚 ++、断粮道 +；超过阈值发"强令回师"，庞涓必须执行但路线/兵力仍有选择。
- 敌方也有 `EnemyKnown`（它眼中的齐军），同样带误差；佯动是否奏效取决于这个认知，不是脚本写死的。
- 困难以上增加"识破"判定：若识破，AI 可走北道、派前队、或回头设伏。

## 5. 前端架构

### 5.1 状态

`stores/game.ts` 一个 composable store：

```ts
const ui = reactive({ view, speed, paused, selectedUnit, reportFilter, decisionOpen })
const session = shallowReactive({ known, reports, orders, node, meta })
function tick() { const r = engine.advanceTick(state); applyResult(r) }   // 只把 KnownState/Report 投影给 UI
```

- 内核状态不进入 Vue 响应式系统（避免深层代理 120 天的数据）；UI 只拿投影后的轻量对象。
- 时钟：`setInterval` 每 tick 间隔（默认 700ms，可调 300/1200ms），节点触发即停；暂停/加速只改定时器，不改内核。

### 5.2 地图

- 单个 `<svg viewBox="0 0 1000 700">`，内部分组：`terrain / rivers / roads / control / cities / units / traces / fog / overlay`。
- 地形与河流是内容包里的 path 数据（手绘），节点坐标同文件。
- 控制区：每个区域的 path + 颜色 + 斜纹 pattern；争夺区用虚线描边 + 双色斜纹。
- 迷雾：用 `<mask>` 或半透明纸纹覆盖未探明区域，不做逐像素噪声。
- 缩放/平移：`<g transform>` + pointer events；手机双指缩放用两指针距离比，桌面滚轮。
- 动效：CSS transition 处理部队移动与色块变化；不做逐帧动画；尊重 `prefers-reduced-motion`。
- 性能：节点 ≤ 30、边 ≤ 50 时 SVG 完全够用；避免大面积 `filter: blur`（低端机掉帧）。

### 5.3 响应式

- CSS 变量 + 容器查询/媒体查询：断点 720px、1080px。
- 竖屏：地图 42vh + 战报流 + 底部控制条；决策面板全屏抽屉。
- 横屏/桌面：两栏 + 底部控制条。
- 触控目标 ≥ 40px；字号 ≥ 13px；用系统字体栈（宋体/黑体回退），不下载字体文件。

### 5.4 可访问性与低配

- 颜色 + 形状/文字双编码；对比度 ≥ 4.5:1。
- 不依赖 hover；全部操作可点按完成。
- 首屏 JS 目标 ≤ 180KB gzip，整包 ≤ 3MB；构建后实测。

## 6. 存档与平台适配

```ts
interface SaveV1 {
  v: 1
  campaignId: string
  difficulty: Difficulty
  seed: number
  state: SerializedSimState     // 含 rng 状态
  known: KnownState
  reports: Report[]
  decisions: DecisionRecord[]
  stats: CampaignStats
  updatedAt: number
}
```

- key：`aiwar.save.v1:<campaignId>`；写入前 JSON 体积检查（>200KB 报警）；损坏时丢弃并保留 `*.bak`。
- 自动存档时机：节点确认后、结算后、`visibilitychange` 隐藏时（节流）。
- 云存档/排行榜适配层 `platform/toySdk.ts`：
  - 通过特性检测判断是否在 Toy 容器内，不在则全部 no-op；
  - MVP 默认只做本地存档；云同步与排行榜作为开关项（需先在发布平台建榜/建共享存档标识），失败静默降级；
  - 调用节奏遵守平台限流：结算时批量写 1 次、排行榜提交 1 次、不轮询、307044 指数退避（最多 2 次）。
- 接口层不写死任何平台全局名；适配文件集中处理，确认 SDK 形态后只改这一处。

## 7. 测试与平衡

### 7.1 单测（Vitest）

- rng：同种子序列一致、按域拆流互不干扰。
- movement：道路日数、疲劳、隐蔽对速度的修正；到达判定。
- combat：双方都有损失、无负数、会战在 3–8 日收敛、伏击首日优势方向正确。
- siege：守方粮尽→城防下降→城破；援军触发撤围。
- logistics：补给线断→粮草只减不增→逃兵；征粮恢复且民心下降。
- intel：探测概率随覆盖/隐蔽/距离单调；误差带落在难度区间。
- nodes：每个节点触发条件可复现；超时走默认选项。
- scoring：各档结局分数落在预期区间；难度系数生效。
- replay：存档→读档→继续推演，与不中断的结果一致。
- 血量检查（类型/内容）：`KnownState` 不含真实数值字段（类型层面 + 快照断言）。

### 7.2 无头对局（平衡）

平衡回归现在是测试用例，不是独立脚本：`pnpm test` 里的 `packages/content/test/balance.test.ts`（围魏救赵四条路线 × 四档难度 × 8 种子）与 `test/regression.test.ts`（四场 ops 战役的历史路线 + 难度梯度单调性）会打印同样的指标，并在跌破底线时失败。

- 策略：史实路线（佯平陵→轻车西驰→桂陵设伏）、直趋邯郸、不救赵，以及各战役的史实决策串。
- 指标：结局分布、均分、评级分布、战役天数、双方折损、伏击成功率。
- 验收：每场战役的史实路线都能打到 A/B 以上；史实难度的分数不低于地狱（容差 ±3 分）；同一 seed + 同一串决策必须复现同一结局。

### 7.3 静态与发布检查

- `pnpm typecheck`（tsc --noEmit）、`pnpm test`、`pnpm build`。
- `pnpm toy:check`（你的 check-toy.mjs，改 CONFIG）。
- `node scripts/preview-toy-subpath.mjs`：把 dist 挂在 `/toy/<slug>/` 下起本地静态服务，验证子路径不白屏（比 vite preview 更接近线上）。
- 可选 `python scripts/toy_doctor.py apps/site/dist --poster cover.png --slug aiwar-guiling --json`。

## 10. 风险与备选

| 风险 | 影响 | 应对 |
|---|---|---|
| SVG 在低端 WebView 掉帧 | 体验差 | 限制节点数、避免滤镜、动效走 CSS、先做真机验证 |
| 语料读多遍出戏 | 沉浸感下降 | 组合式生成 + 分难度语料 + 同模板冷却 |
| 平衡难调 | 结局两极 | 无头批量对局 + 参数集中可调 |
| 平台 SDK 形态与文档不一致 | 云存档不可用 | 适配层特性检测 + 静默降级，MVP 不依赖 |
| 包体安全扫描误报 | 退件 | 运行时只留 Vue；构建后跑 check-toy，必要时登记精确 vendor 基线 |
| 玩法门槛高 | 首局流失 | 3 分钟内的引导：第一份战报 + 第一个决策 + 信息边界提示，均用真实界面带教 |

## 11. 里程碑验收细则

- **M1**：`pnpm dev` 出静态地图与布局；`pnpm build` 后 `toy:check` 0 error；子路径预览不白屏。
- **M2**：内核 10 个单测通过；同种子确定性测试通过；控制台可打印 60 日推演日志。
- **M3**：情报误报/延迟/误差按难度生效；战报语料 ≥ 120 条；迷雾与控制区正确渲染。
