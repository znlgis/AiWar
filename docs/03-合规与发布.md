# 发布合规与自检

> 依据：B 站《Toy 开发者 FAQ》（2026-10-23 版）、《Toy 内容自检清单》、你给的 `check-toy.mjs`（RULES_VERSION 2026-11-12）与 `Toy发布自检.md`。规则会变，发布前以线上 FAQ 和 CLI 报错文案为准。

## 1. 平台硬约束与本作的对应

| 约束 | 官方口径 | 本作做法 |
|---|---|---|
| 包根必须有 index.html | ZIP 根或唯一一级子目录 | Vite 产物直接在 `apps/site/dist`，dist 即包根 |
| 入口 index.html ≤ 1MB（解压后） | 超限提交被拒（307000） | 入口只放挂载点，JS/CSS 走 assets；预算 < 20KB |
| 整包 ≤ 50MB | 更大需单独申请 | 预算 < 3MB，全矢量无素材 |
| 文件后缀白名单 | 非白名单被静默过滤 | 只产出 html/js/css/woff?（本作连字体都不用） |
| 相对路径 | 页面跑在 `/toy/<slug>/`，根绝对路径白屏 | Vite `base: './'`；代码里禁止 `/xxx` 跳转；本地用子路径预览脚本验证 |
| hash 路由可用、history 路由会 404 | 推荐 hash | 单页状态机，不用路由；如后续要分享页再加 hash 路由 |
| 站外链接禁止 | 不得跳转站外 | 游戏内不出现可跳转外链；史料只写书名，不写 URL |
| 外部资源权限收紧 | 未禁止但会逐步收敛 | 零外链：无 CDN、无外部字体、无统计、无 AI 接口 |
| 包体安全检查 | 禁止 eval / new Function / document.write / XHR / WebSocket / atob / webdriver | 运行时只依赖 Vue（runtime-only 构建）；不使用上述 API；构建后跑 check-toy 复核 |
| UGC 能力禁止 | textarea / contenteditable / 文件上传 / 摄像头 / 麦克风都会退件 | 自由文本改为军令拼装器（纯按钮/点选）；无输入框、无上传、无聊天 |
| 内容审核 | 战争题材需注意血腥与政治敏感 | 见 §3 写作规范与敏感词表 |
| 游戏分类限制 | 选「游戏」后未成年人无法游玩 | 接受；游戏定位就是策略推演 |
| 发布后 slug 不可改 | 只允许 `[A-Za-z0-9_-]`，≤64 字节 | 首发前定好 `aiwar-guiling`，更新时保留 |
| 分享链接 | 需带 index.html | 对外分享 `https://www.bilibili.com/toy/aiwar-guiling/index.html` |

## 2. 自检脚本接入

把 `check-toy.mjs` 复制到 `scripts/check-toy.mjs`，只改顶部 CONFIG（规则本体不动，保持和你另外四个项目同一份）：

```js
const CONFIG = {
  name: 'AI 战争模拟器 · 五战',
  dist: 'apps/site/dist',
  zip: 'release/aiwar-guiling.zip',
  sourceRoots: ['apps/site/src', 'packages/sim/src', 'packages/content/src'],
  allowHosts: ['www.w3.org'],   // Vue 运行时的 SVG 命名空间常量，非站外资源加载
  urlTextAllow: ['vuejs.org'],  // 允许出现在说明文字里的项目主页
  sensitiveWords: ['血', '尸', '屠杀', '斩首', '自杀', '色情', '赌博', '毒品', '枪支', '恐怖袭击', '剿总', '民国'],
  securityPatterns: [ /* 原样保留：eval / new Function / document.write / XHR / WebSocket / atob / webdriver */ ],
  requireMeta: true,
  knownVendorHits: [],          // 运行时只有 Vue；w3.org 已由 allowHosts 覆盖，无需登记豁免
}
```

验收：`pnpm build && pnpm toy:check` 输出 0 error。若 Vue 产物触发某条规则，先核对是不是运行时代码，再决定登记精确 vendor 基线或改构建配置——**不能把自有代码的问题混进基线**。

发布前的自动化门禁就是 `scripts/check-toy.mjs`（`pnpm toy:check`）。它覆盖包根、后缀白名单、相对路径、站外加载、代码安全、敏感词、UGC 原语，并在打包后**用 CRC32 校验 zip 与当前 dist 逐字节一致**——旧包不会被误判为可发布。失败必须修，提示项逐条评估（例如 contenthash 已默认开启、频率限制形态本作不涉及）。

## 3. 内容安全

### 3.1 题材处理

- 战争是背景与博弈，不是暴力展示。战斗结果用"小挫 / 损兵 / 大溃 / 溃散 / 俘获 / 大破"表达，不写伤亡细节；结算页的折损也只给分档（数千 / 万余 / 数万 / 十余万），不给精确人数。
- 不出现：尸体、血腥、斩首、酷刑、性、赌博、毒品、现代政治人物、现代国家与国界、现代军事符号。史实页引用公开史料里的数字时注明"各说不一，游戏内只作分档处理"。
- 地图为示意：古代战役用封国/州郡写意图，近现代战役只画战场范围内的城镇与铁路、河流，不画现代行政区划与国界；城邑不标注今地名（今地名只在史实页文字里出现，并注明"示意"）。
- **近现代战役（四渡赤水、淮海）额外约定**：指挥层一律用职务代称（战役总前委、中央红军指挥层），不出现具体人物姓名；建制用"第 N 兵团""绥靖区"等番号，不用旗号、徽记等符号；日期用公元纪年，不用民国纪年。已在 `check-toy.mjs` 的敏感词表里加入"剿总""民国"兜底。
- 结局页与史实页明确写：本作为历史题材的写意改编，地图、兵力、时间线经游戏化处理，不代表严格史实。

### 3.2 文案规范

- 战报、参谋、结局文案统一过一遍敏感词表（脚本可加一条 `pnpm content:scan`）。
- 引用《史记》《孙膑兵法》《战国策》原文控制篇幅（每处 ≤ 40 字），并配白话解释；**引文截断处必须加省略号**，不要悄悄截掉关键分句。
- 古代战役不使用"消灭""歼灭"等现代军事术语，用"破""溃""退"等古语；近现代战役可用"围歼""解决"，但不用血腥细节。
- **通用语料不得带时代标记**：引擎直接发出的战报键（battle.start / intel.sighting / battle.annihilated 等）由五场战役共用，必须写成"鼓角相闻""旗号未明""溃散"这类中性表述；现代词（枪炮、电台、番号、建制）只能放在 `MODERN_CORPUS` 里由近现代战役追加，否则 208 年的长江会打出枪炮声。
- 幽默/吐槽只放在"关于"页的开发者说明里，不放进战报，以免出戏。

### 3.3 未成年人

平台「游戏」分类下未成年人无法游玩，本作不需要额外年龄分级；但文案仍按全年龄标准处理，不做惊悚演出。

## 4. 素材与版权

- 视觉：全部原创 SVG（山形、河线、城郭、旗帜、印章），不引用第三方图片/图标。
- 字体：只用系统字体栈（宋体/黑体回退），不下载字体文件，避免字体版权与体积问题。
- 音效：WebAudio 合成鼓点、号角、翻简声，无音频素材。
- 史料：先秦文献属公有领域，短引用 + 白话注释。
- 依赖：仅 Vue（MIT），构建工具为 devDependency，不进入运行时；产物不打包第三方二进制。
- 封面/图标：用本作视觉素材生成，原创。

## 5. SDK 与限流策略

MVP **不调用任何平台 SDK**，零网络、零云依赖，审核风险最低。

二期可选能力（先在发布平台配置好再写代码）：

| 能力 | 用途 | 节奏要求 |
|---|---|---|
| 云存档 | 跨设备进度 | 只在结算/页面隐藏时批量写；一次调用带全部键；不轮询 |
| 排行榜 | 战役评分 | 结算提交 1 次；只增不减；同分不重复提交 |
| 分享/结果卡 | 传播 | 结算页生成，用户主动点击；失败静默 |

统一约束（官方清单 §7）：不为每次点击/得分写存储；不 `for` 循环逐 key 调；不 `setInterval` 拉榜单；307044 指数退避；不在代码里写死阈值。所有 SDK 调用包在 `platform/toySdk.ts` 的 try/catch 里，任何失败都不影响游戏本身。

## 6. 发布流程

前置：Toy 上传权限（需私信官号申请）、`toy` CLI 已安装并登录。

1. `pnpm check` 全绿（typecheck + test + build + toy:check）。
2. 准备物料：封面（PNG/JPG，4:3，约 1200×900）、图标（独立文件，按要求尺寸，以 `toy create --help-json` 的实际校验为准）、标题、简介、分类「游戏」、可见性。
3. 首次发布：`toy create apps/site/dist --json`（**不带 --yes**，只出预览链接）→ 用户在浏览器验收 → 明确确认后同参数加 `--yes` 提交审核。
4. 更新：`toy mylist --json` 找 id → `toy update <id> apps/site/dist --json` → 预览 → 确认 → `--yes`。**slug 不变**，不删除重建。
5. 提交后进入审核（审核中/已发布/未通过/超时），通过才对外可见。
6. 分享链接带 `index.html`。

命令与 flag 以 `toy --help-json` / `toy create --help-json` 的实时输出为准，不凭记忆写死。

## 8. 风险登记

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 内容审核因战争题材退件 | 中 | 延迟上线 | 文案克制、无血腥、史实说明与免责声明；被拒后按原因改文案重提 |
| 包体安全扫描误报 | 低 | 退件 | 运行时仅 Vue；构建后自检；必要时精确登记基线并注明原因 |
| 子路径白屏 | 低 | 上线即坏 | base './' + 子路径预览脚本 + 真机验证 |
| 低端机 SVG 卡顿 | 中 | 体验差 | 限制图层与动效、真机测试、必要时降级为静态地图+淡入 |
| 玩法门槛高 | 中 | 首局流失 | 首局引导、决策不超过 4 个选项、战报短句、第一次决策给足提示 |
| 平衡失准 | 中 | 口碑 | 无头批量对局调参，发布前留一周观察 |
| 平台政策收紧外部资源 | 低（本作零外链） | 无 | 不依赖外部资源 |
| slug 定错 | 低 | 不可改 | 首发前确认 |
